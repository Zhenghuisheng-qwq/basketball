# CNPA 篮球官网功能实现梳理

> 梳理范围：`basketball-web-ui`、`basketball-web`、`basketball-admin-ui`、`basketball-admin`  
> 梳理时间：2026-07-28  
> 说明：仅基于当前代码与页面，不含运行时联调结论。

---

## 1、核心业务梳理

**球队：**
- 球队是线下自定义组织，新建时 `gameTerminal` 写 `GENERAL`，不应再作为 PC/PS/Xbox 球队本体属性。
- 用户加入的是球队本体；`TeamMembershipSupport` 已实现「一人当前最多一支有效球队」。
- 一支球队可报名同一赛事下不同平台组（`registration.platform_code`）。
- 成员替换可走转会窗口（`RosterChange` API + 后台审核），离队/踢人接口已有。

**队长：**
- 队长权限由后台授予（`basket_captain_qualification`），Web 端无「申请队长」入口。
- 授权可绑定 `seasonId`、`teamId`；Web 端建队/报名/管理球队均走 `CaptainGrantSupport`。
- 赛事结束**不会自动收回**授权，需后台手动 revoke 或等有效期过期。
- 无队长授权时普通用户不能建队（间接实现休赛期限制，但无独立「赛季开关」判断）。

**平台：**
- PC / PS / Xbox 用于游戏 ID 绑定、赛事开放平台（`basket_tournament_season_platform`）、报名平台组、阵容候选校验。
- 用户可绑定多平台 ID；同一用户同一平台一个 ID；同一平台同一 ID 不可重复绑定（服务端校验）。
- 平台字段应在报名记录上，不应在球队本体上——**后端新口径已落地，部分旧逻辑仍残留**。

**篮球位置：**
- PG：控球后卫
- SG：得分后卫
- SF：小前锋
- PF：大前锋
- C：中锋

| 模块 | 当前旧逻辑 | 正确新口径 | 优先级 |

| 队长 | 赛季 finish 不触发 captain revoke | 赛事结束自动或批量收回 | P1 |

| 阵容 | saveRoster 不校验报名平台有效游戏 ID | 提交时强制校验 | P0 |

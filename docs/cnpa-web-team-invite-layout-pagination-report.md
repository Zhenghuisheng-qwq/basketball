# CNPA Web「我的球队 → 邀请成员」布局与分页优化报告

## 1. 当前问题

「邀请成员」页签原先为上下堆叠布局，存在以下体验问题：

1. 候选球员列表无分栏约束，数据多时页面被撑得很长。
2. 「已发送邀请」位于候选列表下方，需滚动到底部才能查看。
3. 邀请说明与发送按钮混在候选列表下方，与已选球员、已发送邀请关系不清晰。

（分页能力已在上一轮实现，本轮在此基础上重构布局与交互。）

## 2. 本轮调整目标

将「邀请成员」页签改为 **左右分栏** 布局：

- **左侧（约 65%）**：邀请候选球员（搜索 + 列表 + 分页）
- **右侧（约 35%）**：当前邀请操作区 + 已发送邀请列表
- **窄屏（≤992px）**：自动上下堆叠
- 两个列表均保持 **每页 5 条** 后端分页

## 3. 修改文件

| 文件 | 变更说明 |
|------|----------|
| `basketball-web-ui/src/views/account/team/index.vue` | 邀请成员页签左右分栏布局、当前邀请卡片、已发送邀请卡片列表、选中球员状态、样式 |

未新增独立组件文件；复用已有 `TeamListPagination.vue` 与 `AccountPanel`。

## 4. 邀请成员左右分栏实现方式

使用 CSS Grid 实现：

```scss
.team-invite-layout {
  display: grid;
  grid-template-columns: minmax(0, 65fr) minmax(0, 35fr);
  gap: 18px;
  align-items: start;
}
```

**左侧**：单个 `AccountPanel`（邀请候选球员）  
**右侧**：上下两个 `AccountPanel`：
1. 当前邀请
2. 已发送邀请

窄屏 `@media (max-width: 992px)` 改为单列 `grid-template-columns: 1fr`。

## 5. 候选球员分页实现方式

- **方式**：后端分页（沿用上一轮实现）
- **接口**：`GET /basket/team/{teamId}/candidate-player/page`
- **参数**：`currentPage`、`pageSize=5`、`keyword`
- **状态**：`inviteCandidatePage = { pageNum, pageSize: 5, total }`
- **分页器位置**：左侧列表底部

## 6. 已发送邀请分页实现方式

- **方式**：后端分页（沿用上一轮实现）
- **接口**：`GET /basket/team/{teamId}/invitation/page`
- **参数**：`currentPage`、`pageSize=5`
- **状态**：`sentInvitePage = { pageNum, pageSize: 5, total }`
- **分页器位置**：右侧已发送邀请列表底部
- **空页回退**：当前页无数据且 `pageNum > 1` 时自动回退上一页

## 7. 是否前端分页

**否。** 候选球员与已发送邀请均使用后端分页接口。

## 8. 是否后端分页

**是。** 两个列表均传 `currentPage` + `pageSize=5`，使用返回 `total` 驱动分页器。

## 9. 每页条数是否为 5

**是。** `TEAM_TAB_PAGE_SIZE = 5`，两个列表固定每页 5 条。

## 10. 搜索后是否回到第一页

**是。** 点击「搜索」时将 `inviteCandidatePage.pageNum` 重置为 1，仅影响候选列表。

## 11. 发送邀请后是否刷新两个列表

**是。** 发送成功后：

1. 清空已选球员（`selectedInvitePlayer` / `selectedInvitePlayerId`）
2. 清空邀请说明
3. 刷新候选列表（保持当前页）
4. 刷新已发送邀请列表（重置为第 1 页）

## 12. 响应式处理

| 断点 | 布局 |
|------|------|
| 桌面端（>992px） | 左 65% / 右 35% 双栏 |
| 窄屏（≤992px） | 上：候选球员 → 中：当前邀请 → 下：已发送邀请 |

- 使用 `minmax(0, …fr)` 防止 Grid 子项撑破横向布局
- 已发送邀请改用紧凑卡片列表，适配窄栏宽度
- 分页器在窄屏下自动换行（继承 `TeamListPagination` 样式）

## 13. 当前邀请区域

| 状态 | 展示 |
|------|------|
| 未选择球员 | 空状态「请选择要邀请的球员」+ 禁用 textarea + 禁用发送按钮 |
| 已选择球员 | 昵称 / 编号 / 平台游戏 ID / 当前球队 + 邀请说明 + 发送按钮 |

选择球员时保存完整 `CandidatePlayerItemDto`，翻页后右侧仍显示已选信息；不会触发页面滚动。

## 14. 已发送邀请展示

因后端 `TeamInvitationItemResp` 当前仅返回昵称、状态、时间、邀请编号等字段（不含球员编号、平台游戏 ID），右侧卡片展示：

- 被邀请球员昵称
- 邀请编号
- 邀请状态（Badge）
- 发送时间
- 邀请说明（若有）

**撤回邀请**：当前项目无撤回/取消邀请 API，未添加操作按钮。

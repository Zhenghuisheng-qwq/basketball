# 21. 表结构总索引

> 本索引以 `sql/basketball.sql` 的 **60** 张基线业务表与 `docs/sql/*.sql` 中新增建表脚本的 **41** 张表取并集，得到仓库层面的 **99 张 `basket_*` 表**。`scripts/expected_tables.json` 目前仅登记 78 张，未覆盖 21 张迁移新增表；而且本轮未连接数据库核对迁移执行状态。因此本文是“源码/迁移资产索引”，不是生产库结构验收报告。

## 1. 业务定位

本文件用于确定每张业务表的所属模块、数据层级、关键字段、唯一性约束与直接写入风险。它服务于开发、联调、数据修复和审计排查，特别用于区分长期主数据、赛事/赛季快照、Submission 流程数据、正式结果、统计快照与日志。

除受控迁移、专用 Service、官方数据修复脚本和经过审核的运维流程外，不应直接写核心业务表。直接 `INSERT` / `UPDATE` / `DELETE` 容易绕过状态机、快照、审计、权限、幂等和统计同步。

## 2. 最终业务规则

1. 所有 `basket_*` 业务表必须有明确模块归属和数据类型：主数据、流程、日志、快照、统计、配置、内容或正式结果。
2. 长期球队、球员、账号等主数据不得替代赛事快照；历史赛事展示必须优先使用赛季阵容、赛事球队和比赛快照字段。
3. `basket_match_data_submission*` 是队长提交和审核流程层；`basket_match_official_result` 与 `basket_match*` 正式统计字段是确认后的正式数据层。
4. 审核、状态变更、统计同步、处罚、公告发布、赛程生成等操作必须经专用 Service 和事务处理，不能直接改状态字段。
5. 表定义、唯一索引和迁移版本应以已执行数据库为最终事实；源码基线、迁移脚本和 `expected_tables.json` 不一致时，必须先做结构差异核对。
6. 所有软删除表应统一使用 `is_delete=0` 作为有效数据口径；纳入唯一索引的软删除字段会影响重建、恢复和历史关联。
7. 统计、排行、积分和荣誉是可重建派生数据，但重建必须由结算/同步流程串行执行，不能人工逐行修正。

## 7. 状态机

```text
账号/认证：账号有效；认证申请 SUBMITTED -> APPROVED | REJECTED
团队成员：申请/邀请 PENDING -> APPROVED | REJECTED/WITHDRAWN；成员 ACTIVE -> LEFT/REMOVED
报名：DRAFT -> SUBMITTED -> REVIEWING -> APPROVED | REJECTED
赛程：生成批次 DRAFT -> 完成；比赛 DRAFT/PUBLISHED -> SCHEDULED -> FINISHED/CANCELLED
Submission：SUBMITTED -> APPROVED(产生正式结果/CONFIRMED) | REJECTED -> 新版本 SUBMITTED
争议/异常：申请 -> 审核中 -> 通过/驳回 -> 修订/处罚/终止
结算：待执行 -> RUNNING -> SUCCESS | FAILED；排行/统计写入对应快照日期
公告：DRAFT/SCHEDULED -> PUBLISHED -> OFFLINE；处罚：生效 -> 到期/撤销
```

表的类型不等于状态机权威来源：例如审核日志只记录过程，主流程表状态和正式结果表才决定业务是否生效。

## 8. 权限规则

1. 账号、资料、隐私、文件、平台账号、消息接收人、收藏等会员数据只能由本人通过专用 Service 读写。
2. 团队、成员、邀请、申请、报名和阵容写入必须校验当前用户、队长授权、对象归属、赛事范围、有效期和状态。
3. 管理员对赛事、赛季、赛程、审核、处罚、公告和统计的写入必须同时校验权限码与 `basket_tournament_admin_scope` 等数据范围。
4. 官网公开接口只能读取公开赛事/赛季、已发布赛程、已确认赛果和允许公开的统计/内容；不得以公开接口回传 Submission、材料、私有资料或审计详情。
5. 任何直接 SQL、生成式 CRUD 或数据修复都必须避免绕过上述边界；对 `/basket/team/**` 遗留入口应优先修复或封禁。

4. `basket_match_data_audit`、Submission 审核和 `basket_match_official_result` 的权威职责需在联调中确认，避免出现两套确认结果。
5. 排行/统计快照表会回读长期球队或球员资料，若未使用对应快照字段，历史展示可能变化。

### P2

1. 多数表使用逻辑关联而非数据库外键；写入顺序和软删除清理依赖应用层，数据修复难度较高。
2. 日志、审计、消息和统计快照持续增长，若无归档策略会影响查询和结算性能。
3. 迁移文件中同时存在 P0、后续 M06/M07 和兼容层资产；必须按批次执行，不能未经产品确认启用后续流程表。

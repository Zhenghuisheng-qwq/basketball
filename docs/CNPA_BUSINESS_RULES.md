# CNPA 我的赛事与队长报名业务规则

> 本文档为 CNPA Web / 后端开发必须遵守的业务口径。Cursor / AI / 开发人员在涉及「我的赛事」、赛事报名、队长授权、参赛端相关功能时，应优先遵循本文档。

## 1. 概念区分

CNPA 平台是赛事组织管理平台，用于：

- 用户注册登录
- 球员认证
- 创建和管理球队
- 邀请成员
- 申请加入球队
- 赛事报名
- 阵容提交
- 审核管理
- 数据展示

CNPA 平台不是实际打游戏的平台，也不是线上支付平台。

PC / PS / Xbox 是游戏端、参赛端、比赛端，只用于：

- 用户绑定游戏 ID
- 赛事开放参赛端
- 赛事报名时选择参赛端
- 阵容成员游戏 ID 校验
- 比赛数据统计分组

**球队不绑定 PC / PS / Xbox 游戏端。**

用户加入的是球队本体，不是某个平台球队。

## 2. 赛事可见范围

所有已登录球员都可以查看公开赛事列表。

无论用户是否加入球队、是否是队长，都可以看到公开赛事。

赛事展示和报名权限必须分开：

- **赛事可见**：所有符合条件的用户可见
- **赛事报名**：只有有效授权队长可操作

不能因为用户不是队长，就把赛事全部隐藏。

## 3. 未加入球队用户

未加入球队的用户可以查看全部公开赛事。

但是不能报名赛事。

按钮状态：

- 显示：**先加入球队**
- 按钮置灰或点击后提示

提示文案：

> 你当前还未加入球队，请先加入球队后，由队长统一报名赛事。

未加入球队用户不能看到：

- 立即报名
- 提交阵容
- 编辑报名
- 撤回报名
- 退出赛事

## 4. 已加入球队但不是队长的普通成员

普通成员也可以查看全部公开赛事。

普通成员可以看到：

- 当前有哪些赛事
- 自己球队是否已经报名
- 自己球队是否具备报名条件
- 自己是否进入阵容
- 赛事详情、赛程、报名状态

普通成员不能报名赛事。

如果普通成员点击报名相关按钮，应提示：

> 当前用户不是球队队长，请联系队长报名。

如果该成员所在球队的队长在某个赛事下有有效队长授权，可以展示：

- 球队具备报名资格
- 等待队长报名
- 联系队长报名

这里的有效期不是普通成员自己的有效期，而是后台授予该球队队长的 **captainGrant** 有效期。

## 5. 队长用户

只有有效授权队长才能报名赛事。

队长报名必须满足：

- 当前用户是球队队长或当前球队授权管理者
- 当前用户拥有有效 captainGrant
- captainGrant 关联当前赛事 eventId / seasonId
- captainGrant 关联当前球队 teamId
- captainGrant 状态为 ACTIVE
- 当前时间在 captainGrant 有效期内
- 赛事处于报名时间内
- 赛事状态允许报名
- 赛事配置了开放参赛端 PC / PS / Xbox
- 当前球队没有重复报名同一赛事同一参赛端

满足条件时，队长可以报名赛事。

不满足时，赛事仍可见，但报名按钮置灰，并展示原因。

## 6. 报名按钮状态规则

赛事列表对所有人可见，但按钮状态根据身份变化：

### 未加入球队

- **按钮**：先加入球队
- **提示**：你当前还未加入球队，请先加入球队后，由队长统一报名赛事。

### 已加入球队但不是队长

- **按钮**：联系队长报名
- **提示**：当前用户不是球队队长，请联系队长报名。

### 队长但无该赛事授权

- **按钮**：暂无该赛事报名资格
- **提示**：当前球队暂未获得该赛事报名资格，请联系管理员确认缴费和授权。

### 队长有授权，但报名未开始

- **按钮**：报名未开始
- **提示**：当前赛事暂未开放报名。

### 队长有授权，但报名已结束

- **按钮**：报名已结束
- **提示**：当前赛事报名已结束。

### 队长有授权，报名中，且未重复报名

- **按钮**：报名赛事
- 点击进入报名流程。

### 已报名

- **按钮**：查看报名 / 管理报名
- 不能重复报名同一赛事同一参赛端。

## 7. 赛事报名和参赛端

球队不绑定 PC / PS / Xbox。

报名赛事时，才选择参赛端。

例如：

- crb 报名 2026 常规赛 PC 组
- crb 报名 2026 常规赛 PS 组

报名记录必须保存：

- eventId / seasonId
- teamId
- platformCode，表示参赛端
- captainGrantId
- registrationStatus

同一球队同一赛事同一参赛端不能重复报名。

## 8. 阵容校验

阵容属于某条报名记录。

阵容校验时才检查 PC / PS / Xbox 游戏 ID。

例如：

报名 PC 组，则阵容成员必须拥有已生效 PC 游戏 ID。

**加入球队阶段不检查 PC / PS / Xbox 游戏 ID。**

## 9. 术语规范

不要写：

- 球队平台
- PC 球队
- PS 球队
- Xbox 球队
- 当前平台球队

推荐写：

- 参赛端
- 游戏端
- 报名平台
- 开放参赛端
- 球队
- 当前球队

## 10. 后端权限校验（报名接口）

前端按钮只负责体验，后端报名接口必须校验：

- 当前用户已登录
- 当前用户是球队队长或授权管理者
- 当前用户有该赛事有效 captainGrant
- captainGrant.teamId 匹配当前球队
- captainGrant.eventId / seasonId 匹配当前赛事
- 当前时间在授权有效期内
- 赛事处于报名期
- 所选参赛端已开放
- 当前球队未重复报名同一赛事同一参赛端

普通成员即使绕过前端直接调报名接口，也必须失败。

错误提示：

> 当前用户不是球队队长，不能代表球队报名赛事。

或（无该赛事授权时）：

> 当前球队暂未获得该赛事报名资格，请联系管理员确认缴费和授权。

# 队长授权与报名资格规则

1. CNPA 是赛事组织管理平台，不是真正打游戏的平台。
2. PC / PS / Xbox 是游戏端、参赛端、报名平台，不是球队所属平台。
3. 球队是 CNPA 平台内管理的球队本体，不绑定 PC / PS / Xbox。
4. 用户加入的是球队本体，不是某个平台球队。
5. 用户不能主动申请成为队长。
6. 队长权限由后台工作人员根据线下缴费结果人工授予。
7. 队长授权必须绑定具体赛事 eventId（数据库字段 `season_id`）。
8. 队长授权必须绑定具体球队 teamId，或者先创建授权后再绑定球队。
9. 队长授权有效期只表示这条授权是否过期，不代表该时间段内所有赛事都能报名。
10. 能不能报名赛事，必须看当前用户、当前球队、当前赛事是否存在匹配的有效队长授权。
11. 正确报名资格判断必须按 userId + teamId + eventId 匹配 captainGrant（`basket_captain_qualification`）。
12. 如果赛事还区分参赛端，则报名记录再保存 platformCode。
13. 赛事所有已登录认证球员都可以看到，但只有有效授权队长可以报名。
14. 普通成员可以看赛事和球队报名状态，但不能报名。
15. 未加入球队用户可以看赛事，但不能报名。
16. 队长授权涉及缴费、赛事资格、球队报名，必须保留历史日志（`basket_captain_grant_log`）。

## 队长授权主表

复用 `basket_captain_qualification`，语义等同队长授权主表 `basket_captain_grant`。

关键字段映射：

| 业务字段 | 数据库字段 |
|---------|-----------|
| grant_no | qualification_no |
| user_id | member_id |
| event_id | season_id |
| grant_status | qualification_status（1=ACTIVE, 0=REVOKED, 2=EXPIRED） |
| grant_time | granted_time |
| expire_time | valid_to |
| revoke_time | revoked_time |
| grant_by | granted_by |
| revoke_by | revoked_by |
| payment_ref_no | payment_reference |
| grant_remark | grant_reason |

## 队长授权日志

`basket_captain_grant_log` 记录 GRANT / BIND_TEAM / REVOKE / EXPIRE 等操作，供后台详情页「授权日志」展示。

## 后台操作与通知

- **授予**：校验球员认证、缴费确认、赛事未结束 → 写主表 + 日志 + 站内通知
- **绑定球队**：校验授权 ACTIVE、球队存在 → 更新 teamId + 日志 + 通知
- **收回**：仅后台可操作 → 状态 REVOKED + 日志 + 通知
- **赛事结束过期**：批量 EXPIRED + 日志（SYSTEM）+ 通知

# CNPA Web「历史邀请」弹窗分页与可读性修复报告

## 1. 当前问题

「我的球队 → 邀请成员 → 历史邀请」弹窗存在以下问题：

1. 历史邀请列表未真正分页，超过 5 条时一次性全部展示。
2. 后端 `total=0` 但 `records` 返回全量，导致分页器不显示。
3. 有数据时仍显示「暂无邀请记录」空状态（因空状态判断使用了 `total === 0`）。
4. 弹窗 Teleport 到 `body` 后继承站点浅色文字，表格内容发白难以阅读。
5. 弹窗背景半透明，与遮罩混色。
6. 搜索/状态筛选的分页刷新逻辑不完整（关键词模式依赖错误的 total 循环终止条件）。

## 2. 分页修复方式

### 后端（主路径）

接口 `GET /basket/team/{teamId}/invitation/page` 已支持 `currentPage`、`pageSize`、`status`。

修复 `TeamInvitationBusinessServiceImpl.pageTeamInvitations()`，采用 web 端统一写法（与消息通知一致）：

- `selectCount` 获取 `total`
- `selectList` + `LIMIT offset, size` 只返回当前页数据

历史邀请弹窗参数：

- `pageSize = 5`（固定）
- `pageNum` 默认 1
- 翻页保留 `keyword` / `status`
- 搜索 / 状态切换 → `pageNum = 1`
- 关闭弹窗再打开 → 重置筛选并回到第 1 页

### 前端（关键词搜索兜底）

后端接口暂不支持 `keyword` 参数。有关键词时：

1. 分页拉取全部邀请（修正循环终止条件）
2. 前端按昵称 / 邀请编号 / 说明过滤
3. 前端切片每页 5 条

无关键词时直接使用后端分页。

## 3. 空状态修复方式

| 场景 | 显示 |
|------|------|
| 加载中 | 「加载中…」，不显示空状态 |
| 当前页有数据 | 表格，不显示空状态 |
| 无数据 + 有搜索/筛选 | 「暂无符合条件的邀请记录」 |
| 无数据 + 无搜索/筛选 | 「暂无邀请记录」 |

判断依据改为 **`historyInvitePagedRecords.length === 0`**，不再单独用 `total === 0` 触发空状态。

## 4. 字体颜色 / 可读性修复方式

针对 `.team-dialog__panel--history`：

- 实体白底 `#fff`，主文字 `#111`
- 表头 `#333`，表格行 `#222`，次要文字 `#666`
- 搜索框白底深字，placeholder `#9ca3af`
- 状态筛选按钮白底 `#333`，选中态 `#fff5f5` + 红色边框
- 遮罩 `z-index: 0`，弹窗面板 `z-index: 1`，避免层级混乱
- 弹窗 `max-height: 85vh`，内容区内部滚动

## 5. 是否使用后端分页

**是（无关键词时）。**

有关键词搜索时，因接口不支持 keyword，采用**前端过滤 + 前端切片分页**。

## 6. 前端分页说明

仅在有 `keyword` 时启用前端分页模式（`historyInviteClientMode`）。原因：后端 invitation/page 接口无 keyword 参数，不能改接口语义。

## 10. 遗留问题

1. 关键词搜索仍为前端过滤，数据量极大时可能偏慢；后续可在后端增加 keyword 参数。

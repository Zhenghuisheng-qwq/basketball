# CNPA Web「我的球队」页签分页优化报告

## 1. 本轮目标

为「我的球队」页面中以下三个页签增加分页展示，每页固定 5 条，不改业务逻辑与数据库结构：

1. **邀请成员** — 候选球员列表 + 已发送邀请列表
2. **加入审核** — 待处理加入申请列表
3. **赛事报名** — 可报名赛事列表 + 报名记录列表

## 2. 修改的文件

| 文件 | 变更说明 |
|------|----------|
| `basketball-web-ui/src/views/account/team/index.vue` | 三个页签分页状态、加载函数、分页器 UI、操作后刷新逻辑 |
| `basketball-web-ui/src/stores/team.ts` | 列表加载方法返回 `PageResult`，便于前端读取 `total` |
| `basketball-web-ui/src/components/account/team/TeamListPagination.vue` | **新增** 可复用分页组件（CNPA 黑红风格） |

## 3. 邀请成员 — 候选球员分页

- **实现方式**：后端分页
- **接口**：`GET /basket/team/{teamId}/candidate-player/page`
- **参数**：`currentPage`、`pageSize=5`、`keyword`（可选）
- **前端状态**：`inviteCandidatePage = { pageNum, pageSize: 5, total }`
- **搜索**：点击「搜索」时将 `pageNum` 重置为 1 后请求
- **分页切换**：保留当前搜索关键词
- **发送邀请后**：刷新候选列表（当前页）与已发送邀请列表（第 1 页）

## 4. 已发送邀请分页

- **实现方式**：后端分页
- **接口**：`GET /basket/team/{teamId}/invitation/page`
- **参数**：`currentPage`、`pageSize=5`
- **前端状态**：`sentInvitePage = { pageNum, pageSize: 5, total }`
- **空状态**：「暂无邀请记录」
- **发送邀请后**：跳至第 1 页刷新，确保新邀请可见

## 5. 加入审核分页

- **实现方式**：后端分页
- **接口**：`GET /basket/team/{teamId}/join-application/page`
- **参数**：`currentPage`、`pageSize=5`、`status=0`（待处理）
- **前端状态**：`joinAuditPage = { pageNum, pageSize: 5, total }`
- **审核通过/驳回后**：刷新当前页；若当前页无数据且 `pageNum > 1`，自动回退上一页
- **空状态**：「暂无加入申请」

## 6. 赛事报名分页

### 6.1 可报名赛事（队长可见）

- **实现方式**：后端分页
- **接口**：`GET /basket/team/{teamId}/registration/available-season/page`
- **参数**：`currentPage`、`pageSize=5`
- **前端状态**：`availableSeasonPage = { pageNum, pageSize: 5, total }`
- **空状态**：「当前暂无可报名赛事」

### 6.2 报名记录

- **实现方式**：后端分页
- **接口**：`GET /basket/team/{teamId}/registration/page`
- **参数**：`currentPage`、`pageSize=5`
- **前端状态**：`registrationListPage = { pageNum, pageSize: 5, total }`
- **空状态**：「暂无报名记录」
- **报名/撤回/删除草稿/创建草稿后**：刷新两个列表的当前页

## 7. 是否使用后端分页

**是。** 上述 5 个列表均使用已有后端分页接口，传 `currentPage` + `pageSize=5`，并使用返回的 `total` 驱动分页器。

## 8. 前端分页说明

本轮**未使用**前端切片分页。项目 API 层已统一支持 `PageResult`，直接复用后端分页。

## 9. 每页条数

**是，统一为 5 条。** 常量 `TEAM_TAB_PAGE_SIZE = 5`，分页组件不暴露 pageSize 切换。

## 10. 搜索后是否回到第一页

| 列表 | 是否重置为第 1 页 |
|------|-------------------|
| 候选球员搜索 | 是 |
| 加入审核（当前无筛选 UI） | N/A |
| 赛事报名（当前无搜索 UI） | N/A |

## 11. 操作后是否刷新列表

| 操作 | 刷新行为 |
|------|----------|
| 发送邀请 | 候选列表（当前页）+ 已发送邀请（第 1 页） |
| 审核通过/驳回 | 加入审核（当前页，空页自动回退） |
| 创建/提交/撤回/删除报名 | 可报名赛事 + 报名记录（各自当前页） |

## 14. 遗留问题

1. 赛事报名页签「可报名赛事」与「报名记录」共用 `teamStore.registrationLoading`，同时翻页时可能互相显示 loading，不影响数据正确性。
2. 分页器在总条数 ≤ 5 时自动隐藏（`total > pageSize` 才展示），符合项目现有 JoinableTeamPanel 风格。
3. 报名详情内的「阵容候选成员」「审核记录」子列表本轮未分页（不在需求范围内）。

# CNPA 篮球官网 Cursor 第一轮自动测试清单

> 目标：让 Cursor 先对 `basketball-web-ui`、`basketball-web`、`basketball-admin-ui`、`basketball-admin` 做一轮只检查、只测试、只汇总的业务预验收。
>
> 本轮禁止开发、修复、重构和改表。发现问题只记录，最终生成 `CNPA_TEST_REPORT.md`。

---

## 一、执行原则

### 1. 禁止事项

- 禁止新增功能。
- 禁止修改代码和数据库。
- 禁止为了通过测试而绕过权限或状态。
- 禁止把“有页面”“有接口”“有表”直接判定为已完成。
- 禁止把 Mock 数据当成真实实现。
- 禁止自动修复问题。

### 2. 允许事项

- 检查目录、菜单、路由、页面、接口、状态和数据表。
- 启动、编译、构建四个项目。
- 使用现有测试账号和测试数据。
- 调用本地接口并查询数据库验证结果。
- 对比前台提交、后台处理和官网展示是否使用同一份数据。

### 3. 完成度标准

每个模块只能使用以下结论：

- 已完整实现
- 基本实现
- 部分实现
- 仅有页面
- 仅有数据结构
- 未实现
- 存在严重问题
- 暂时无法验证

“已完整实现”必须同时满足：

1. 正常流程可跑通。
2. 异常操作有正确限制。
3. 权限正确。
4. 状态流转完整。
5. 数据真实保存。
6. 后台处理结果能反馈前台。
7. 结果可被下一业务环节继续使用。
8. 历史或审核记录可追溯。

# 七、五条全链路预验收

## 链路一：普通球员

```text
注册
→ 登录
→ 自动建立球员档案
→ 完善资料
→ 提交认证
→ 后台审核
→ 前台显示认证结果
```

## 链路二：队长和球队

```text
认证球员
→ 授予队长资格
→ 创建球队
→ 邀请成员
→ 成员加入
→ 提交球队认证
→ 后台审核
```

## 链路三：报名和阵容

```text
创建赛事
→ 发布赛事
→ 开启报名
→ 认证球队报名
→ 后台审核
→ 提交阵容
→ 阵容审核
→ 阵容锁定
```

## 链路四：比赛和数据

```text
创建比赛
→ 设置对阵
→ 开始比赛
→ 录入比分
→ 录入球员数据
→ 完赛
→ 数据审核
→ 更新积分榜和排行榜
```

## 链路五：处罚和归档

```text
创建处罚
→ 限制球员或球队
→ 影响阵容、报名或积分
→ 处罚到期或撤销
→ 赛事结束
→ 赛事归档
→ 形成历史档案和荣誉
```

每条链路必须输出：

- 可以完整跑通，或只能跑到哪一步。
- 从哪一步开始失败。
- 失败原因。
- 缺少的页面、状态、权限或数据。
- 是否需要人工验证。

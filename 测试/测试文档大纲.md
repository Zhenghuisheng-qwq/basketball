## 1. 文档说明

### 1.1 编写目的

- 熟悉 CNPA 篮球赛事平台的完整业务。
- 明确每个功能解决什么问题。
- 明确不同角色可以执行哪些操作。
- 通过实际测试判断功能是否真正实现。
- 核对前台、个人中心、后台管理之间是否形成完整业务闭环。
- 熟悉所有核心业务表及其用途。
- 记录当前系统存在的问题、缺失项和不合理设计。
- 形成可以向老板说明项目进度和业务方案的材料。

### 1.2 使用方式

每次只处理一个业务模块，按照以下顺序进行：

1. 先理解业务目标。
2. 再查看系统当前页面和操作入口。
3. 查看 Cursor 对该模块的实现说明。
4. 查看相关数据库表。
5. 按正常流程进行实际测试。
6. 测试失败、拒绝、重复提交、越权等异常流程。
7. 核对前后台状态和数据是否一致。
8. 评估当前完成度。
9. 记录问题和后续待办。
10. 输出一段可以用于汇报的业务总结。

### 1.3 本文档不包含的内容

- 不讨论具体代码语法。
- 不讲 Controller、Service、Mapper 应该怎么编码。
- 不以接口数量作为完成度判断标准。
- 不因为页面存在就判定业务已经完成。
- 不因为数据库有表就判定业务已经实现。
- 不讨论正式部署、域名、备案、Nginx、HTTPS 等上线内容。
- 测试期间优先关注业务正确性、状态闭环、权限和数据一致性。

## 2. CNPA 系统整体业务概览

### 2.1 项目定位

CNPA 是一个线上篮球游戏赛事平台，主要包括：

- 公开官网
- 玩家和队长个人中心
- 后台赛事管理
- 球员、球队、报名、比赛和数据统计体系
- 公告、处罚、档案和内容运营体系

### 2.2 核心业务主线

完整核心链路：

```text
账号注册与登录
→ 球员档案
→ 球员认证
→ 队长资格
→ 球队创建
→ 成员管理
→ 球队认证
→ 赛事管理
→ 赛事报名
→ 参赛阵容
→ 比赛执行
→ 数据统计
→ 数据与业务审核
→ 处罚与历史档案
→ 公告与内容运营
```

## 4. 测试结论与完成度标准

### 4.1 完成度等级

#### 已完整实现

- 正常流程可以完成。
- 异常流程有明确限制。
- 权限控制正确。
- 前后台状态一致。
- 数据能够正确沉淀。
- 后续业务可以继续使用该结果。

#### 基本实现

- 主流程可以完成。
- 少量异常场景或边界规则缺失。
- 不影响主要演示和基础使用。

#### 部分实现

- 只有部分操作可以使用。
- 前后台没有完全闭环。
- 状态流转不完整。
- 数据不能继续支撑后续业务。

#### 仅有页面

- 页面可以打开。
- 使用 Mock 数据或固定数据。
- 提交后没有真实状态变化。
- 后台无法看到或处理。

#### 仅有数据结构

- 数据库表已经存在。
- 页面和业务操作尚未完成。
- 暂时无法通过系统验证。

#### 未实现

- 没有页面。
- 没有操作入口。
- 没有实际业务能力。

#### 存在严重业务问题

- 权限越权。
- 状态可以随意跳转。
- 数据前后不一致。
- 重复操作产生重复数据。
- 审核结果未影响实际业务。
- 已处罚对象仍可继续参加比赛。

#### 暂时无法验证

- 缺少测试账号。
- 缺少基础数据。
- 缺少后台权限。
- 缺少赛事、球队或比赛样本。
- 当前环境无法完成流程。

### 4.2 单模块完成度记录表

| 项目 | 结论 |
|---|---|
| 页面是否存在 | 待验证 |
| 正常流程是否可用 | 待验证 |
| 后台是否可处理 | 待验证 |
| 状态是否完整 | 待验证 |
| 权限是否正确 | 待验证 |
| 数据是否真实保存 | 待验证 |
| 是否支持异常处理 | 待验证 |
| 是否形成后续业务结果 | 待验证 |
| 当前完成度 | 待评估 |


# 第一部分：账号与球员身份

## 6. 账号注册与登录

### 6.1 需求范围

- 邮箱注册。
- 邮箱验证码。
- 设置密码。
- 登录。
- 退出登录。
- 忘记密码。
- 重置密码。
- 登录状态保持。
- 账号禁用。
- 重复邮箱限制。
- 验证码有效期和重复发送限制。

### 6.2 核心业务问题

- 邮箱是否是唯一账号。
- 注册成功后是否自动成为球员。
- 注册时是否必须选择 PC 端或手机端。
- 登录后进入哪里。
- 被禁用账号是否还能登录。
- 修改邮箱是否允许。
- 注销账号是否在第一期范围内。

### 6.3 重点测试场景

- 正常邮箱注册。
- 已注册邮箱重复注册。
- 错误验证码。
- 过期验证码。
- 多次发送验证码。
- 密码错误。
- 被禁用用户登录。
- 登录过期。
- 未登录访问个人中心。
- 退出后再次访问受限页面。

```text
→ 成员加入

→ 后台审核
```


- 禁赛球员。
- 阵容变更。

## 31. 比赛与数据链路

```text
创建比赛
→ 安排对阵
→ 比赛开始
→ 录入比分
→ 录入球员数据
→ 完赛
→ 数据审核
→ 更新战绩与排行榜
```

需要核对：

- 比分和球员得分一致性。
- 未审核数据是否展示。
- 审核后官网是否更新。
- 修改数据后是否重新统计。

## 32. 处罚影响链路

```text
创建处罚
→ 处罚生效
→ 限制报名或阵容
→ 扣分或禁赛
→ 官网和后台显示
→ 到期或撤销
```

需要核对：

- 处罚是否真正影响业务。
- 禁赛是否阻止参赛。
- 扣分是否改变积分榜。
- 撤销后是否恢复。

## 33. 赛事归档链路

```text
赛事结束
→ 所有比赛完成
→ 数据审核完成
→ 生成最终排名
→ 归档赛事
→ 形成球队和球员历史
→ 产生冠军与荣誉
```

需要核对：

- 赛事结束条件。
- 未审核数据是否允许归档。
- 归档后是否仍能修改。
- 名人堂是否正确生成或维护。
